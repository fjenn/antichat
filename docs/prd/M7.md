### 0.1 Global preconditions (apply to every task)

2. **Human-only (PRD §9), never blocking:**
   - `COMPOSIO_API_KEY`, `INSTALL_ID_HMAC_SECRET`, `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` set in the Vercel project `antichat-relay` (architecture §8.3). **Meanwhile:** stub key `dev-not-a-key` → relay answers `503 relay.notConfigured`; app shows `relay.notConfigured`; the relay E2E does **not** use the stub key (it would stop at 503): it runs with `relay/.env.test` (`COMPOSIO_API_KEY=test-mock-key`, `COMPOSIO_BASE_URL` → `relay/test/mock-composio.ts`) replaying `fixtures/web/mcp/composio-*.jsonl` (M7.T10).
   - Vercel account access for preview deploys (`vercel login` as the user). **Meanwhile:** `make relay-dev` and `make site-dev` locally. `vercel dev` itself needs a logged-in, linked CLI, so `make relay-dev` (implemented in M7.T10) runs `npx vercel dev --listen 3000` only when `npx vercel whoami` exits 0, and otherwise runs the no-login adapter `npx tsx relay/scripts/local-server.ts` (node:http on `http://127.0.0.1:3000` mounting the same `api/v1/*` handlers); env from `relay/.env.local` (gitignored, generated by `relay/scripts/make-env.ts` with a random `INSTALL_ID_HMAC_SECRET`). The Vercel CLI is an exact-pinned devDependency of `relay/` (not a global tool).
   - **Real Composio E2E** additionally needs a test Gmail account signed in through Composio's browser flow (human OAuth, not listed in PRD §9). It runs only when `COMPOSIO_API_KEY` is set **and** the user has written `COMPOSIO_TEST_ACCOUNT=<address>` into `relay/.env.local`; otherwise it is recorded "not run (human)" and deferred to ci-release §8 item 19. It never blocks M7 exit.
   - A public HTTPS URL for the CIMD document (production domain is M10). **Meanwhile:** a Vercel preview of `site/` serving `site/public/oauth/mcp-client-metadata.json`; if no Vercel access either, AT-257 runs against the local reference authorization server `tools/mcp-ref/` which accepts an `http://localhost` CIMD URL in its test mode only (documented [ASSUMPTION]; re-run against the preview URL when available).
   - 20% human spot-check for R-250 AC2 (see §0.2).
3. **Network:** every byte goes through `NetworkGate` (M2, G-056) using the existing M2.T02 `NetworkCategory` cases only: `.search` (engines, BYO providers **and** page fetches, R-297 `web_search`), `.mcp` (remote MCP servers, OAuth endpoints), `.relay` (Composio relay); no new category is added. Where an ephemeral (cookie-less) session is needed, M7.T02 adds the overload `NetworkGate.session(for:configuration:)` in `AntiChatNetwork` (keeps `GateURLProtocol`; covered by `SwizzleCoverageTests`). Nothing here creates a `URLSession` outside `AntiChatNetwork` (architecture §3 rule 5).
4. **No filters (D-005/D-006, R-241):** no task in M7 adds a content check, keyword list, safety prompt or refusal override. Untrusted-content marking (NFR-SEC5) is a provenance label plus a confirmation rule on tool calls, not a filter; it is on the R-241 allow-list with that justification (M7.T15).
