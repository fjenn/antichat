## Conventions used in this file

- **P-Q007 (precondition of every task):** cloning, building and running code in `~/AntiChat` is allowed (Q-007 cleared at M0 entry). If the sandbox, an auto-mode classifier or macOS refuses a command, stop that task, write the exact command and error into `docs/research/QUESTIONS.md` (PRD §1.5 case 1), and continue with tasks that don't need it.
- **[PERM: …]** marks an extra permission-dependent step: a macOS TCC grant (microphone), an admin install (virtual audio device), a computer-use grant, or network access for model downloads.
- **AT runner:** every AT command is run as `tools/at/run.sh <AT-ID> -- <command…>` (M1.T02, M1 convention 2). It tees output to `build/at/<AT-ID>/<YYYY-MM-DD>.log` and writes `build/at/<AT-ID>/result.json` (`{id, date, commit, cmd, exit, pass}`).
- **`$XUI`** = `xcodebuild test -workspace AntiChat.xcworkspace -scheme AntiChat-UITests -destination 'platform=macOS,arch=arm64' -resultBundlePath build/xcresult/<AT-ID>`.
- **`$XINT FILTER=<Suite>[/<test>]`** = `make test-integration-real TIER=T1 FILTER=<Suite>[/<test>]` (M1 convention 3: real XPC helper + real models; pass `TIER=T3` for T3-cap runs). Integration suites live in `Packages/Engines/Tests/AntiChatEnginesTests/` and are tagged `@realModels`; there is no separate package scheme.
- **Unit tests:** `make test-unit FILTER=<TestClass>` (= `swift test --parallel --filter <TestClass>`).
- **Perf:** `make perf METRIC=<NFR id without prefix> TIER=<cap> [RUNS=20]` (M1.T26: `tools/perf/run.py`) merges into `build/perf/report.json`, key `.metrics.<id>.<tier>` = `{p50, p95, p99, n, unit, target, pass, method}` (M1.T26 schema; per-stage values as sub-keys `.metrics.V2.T3.stages.<stage>`); ≥ 20 runs (test-strategy §6). One metric per call (run several with a shell loop). Targets come from `tools/perf/nfr_targets.json`, generated from `nfr.md` by ID; never retyped. **Each task that first defines an AT-NFR-V* adds its probe to `tools/perf/run.py`** (driving `antichat-bench voice`, the M0.T05 `-Bench voice` mode, or the named XCUITest perf test) and records the input mode in `method`/a `mode` field: `inject` (ScriptedVoice / in-pipeline, label `[IN-PIPELINE]`) or `blackhole`.
- **Real models:** `make models-dev TIER=T1` (and `TIER=T3` for T3-cap runs) [PERM: network to huggingface.co, anonymous, pinned commits]. Single extra keys: `antichat-cli models install --catalog catalog/dev-catalog.json --keys <key>[,<key>]` (if M2's `antichat-cli` has no `--keys` filter, add it in the first task that needs it; minor).
- **Test-only launch arguments added in this file** (`#if DEBUG`, parsed in `Packages/Foundation/Sources/AntiChatFoundation/TestHooks.swift`, M2 convention): `-UseScriptedVoice <script.jsonl>` (M3.T03), `-FakePermission microphone=<notDetermined|denied|granted>` (M3.T02), `-FakePackState voice=<absent|downloading|ready>` + the test hook `TestHooks.setPackState` (M3.T04), `-FakeAudioDevices <none|drop-after=<n>s>` (M3.T08), `-FakeAEC unavailable`, `-FakeAudioRoute headphones` and `-VoiceTestHarness <script.json>` (M3.T12). 4. `barge-in/` (36 items = 12 × 3 rooms): `tts` stem = a Kokoro sentence (from `tools/fixtures/barge-in-texts.txt`, 12 fixed assistant sentences of 15–25 words written in this task, synthesised offline with `tts` voice `af_heart` via `antichat-bench voice --synthesize`) and `user` stem = a test-clean utterance; rooms = synthetic RIRs RT60 0.3 / 0.5 / 0.8 s (`rir.py`, exponential-decay noise, seeded); files `itemNN-roomK-user.wav` (user stem convolved, starting at `onset_ms` ∈ [800, 3000] ms after TTS start), `itemNN-roomK-tts.wav`, `itemNN-roomK-mic.wav` (both convolved and mixed at speech-to-echo ratio 0 dB); `manifest.json` `{item, room, onset_ms, tts_text}`.
5. `long-file/long-60min.wav`: test-clean utterances (excluding all above) concatenated with 0.5 s gaps to 60:00 ± 5 s, plus `long-60min.txt` with `[hh:mm:ss]` per utterance. Environment §4 says "Kokoro-generated script"; real speech is used instead so the transcript is ground truth (amendment **A-M3-05**, minor: fixture source).
6. `noise/`: `fan.wav` (brown noise + 120 Hz hum), `cafe.wav` (babble: 8 test-clean utterances summed at random offsets + clatter impulses), `keyboard.wav` (synthetic clicks at 5–8 Hz), 60 s each, normalised to −30 dBFS RMS; labelled synthetic in `SOURCES.md`.
7. `music/bed-60s.wav`: a synthetic chord progression (sine + harmonics, 44.1 kHz stereo, −20 dBFS RMS) used for the ducking checks (M3.T12, vq-08 step 23) so no music library or account is needed.
