### Shared test conventions (all tasks)
- Unit/integration: `make test-unit FILTER=<TestClass>` = `swift test --parallel --filter <TestClass>`; integration with the helper: `make test-integration-stub FILTER=<TestClass>`; real models: `make test-integration-real TIER=<T> FILTER=<TestClass>`.
- **`FILTER` lists:** a comma list (`FILTER=A,B,C`) is expanded by the Makefile — `swift test --filter '\.(A|B|C)(/|$)'` (one regex) for unit/integration, one `-only-testing:AntiChatUITests/<X>` per item for UI, one run per metric for `make perf METRIC=…`. Every test target **fails when 0 tests ran** (a mistyped filter must never pass vacuously). If M1's Makefile lacks this, M2.T02 adds it (minor).
- **`TIER` vs `CAP`:** in `make models-dev` / `make test-integration-real`, `TIER` names a **model set** (`min`, `T1`, `T3`, `evil-T1`, `evil-T3`; environment §6); the hardware cap defaults to the set's tier (T1 for `T1`/`evil-T1`, T3 for `T3`/`evil-T3`, none for `min`) and is overridden with `CAP=<tier|sub-band>` (e.g. `CAP=T2-24`), passed to `antichat-bench --cap` (M1 convention). In `make perf`, `TIER` is the **cap**.
- **Import edges (architecture §3):** `AntiChatHarness` may not import `AntiChatPlatform` or `AntiChatNetwork`, and the helper's `AntiChatEngines` may not import `AntiChatPlatform`. Harness code that needs catalog, download, hardware or gate data (T03 `TurnNetworkLedger`, T17 `ToneClause`, T20 `StarterHandoff`, T24 `InstallCardPolicy`) declares a small protocol in Harness (`NetworkEventSource`, `ToneSentenceProviding`, `ModelReadinessProviding`, `PackInstalling`); the conformances live in `AntiChatUI` (which imports both) and are injected at the composition root. The scheduler gets B, keep-alive and power state only through `SetPolicy` (T12). No new edge is added to `tools/ci/import-graph.py` except Platform → `TUFFVendored` (T09).
- **Runbook sections:** a task whose Visual QA script names a `tools/visual/vq-##-*.md` § adds that section (creating the file from the test-strategy §5 list if absent, e.g. `vq-11-failures.md`); M2.T26 consolidates and executes all of them.
- UI: `make test-ui FILTER=<Class>` = `xcodebuild test -workspace AntiChat.xcworkspace -scheme AntiChat-Debug -destination 'platform=macOS,arch=arm64' -only-testing:AntiChatUITests/<Class>`.
- Perf: `make perf METRIC=<NFR id without prefix> TIER=<T>` writes `build/perf/report.json` key `nfr.<ID>.<TIER>` = `{p50, p95, n, bar, pass, scaled:[INFERENCE]?}` (≥ 20 runs, test-strategy §6).
- Every AT writes `build/at/<AT-ID>/<yyyy-mm-dd>.log` (stdout + the xcresult summary via `xcrun xcresulttool get --format json`) and commits it (PRD §1.4 rule 1).
- New test-only launch arguments added in this milestone (Debug builds only, `#if DEBUG`, parsed in `Packages/Foundation/Sources/AntiChatFoundation/TestHooks.swift`): `-FakeHardware <fixture>` (exists from test-strategy §4.2; the fixture files are created in M2.T01), `-FakeFreeDiskGB <n>`, `-FakeNetwork none|expensive|constrained|ok`, `-FakePower ac|battery:<pct>|lowpower`, `-FakeThermal nominal|serious|critical`, `-CatalogURL <url>`, `-CatalogTestKeys YES`, `-DownloadHost <url>` (rewrites `https://huggingface.co` to a local fixture server), `-TestProxy <host:port>` (T03), `-PrintHardwareProfile YES` (T01), `-FakePressure warn|critical` (T14), `-FakeLAContext succeed|fail` (T17), `-SkipOnboarding YES` (T18). Because these exist only in Debug, every run that uses them (UI tests, AT-VQ-M2) uses the ad-hoc-signed **Debug** build from `make build`.
- New copy keys are added to `docs/research/10-architecture/design-system/copy-deck.md` **and** `Packages/UI/Sources/AntiChatUI/Resources/Localizable.xcstrings` in the same commit (H5, `tools/ci/copy-sync.py`). Adding a key whose text is quoted verbatim from a requirement is a minor amendment only if the requirement text differs from the copy deck.
