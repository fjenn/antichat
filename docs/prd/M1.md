## 0. Conventions used by every task in this file

1. **Permission precondition (Q-007, PRD §1.5.1).** Every task below builds and runs code in `~/AntiChat`, so it requires Q-007 cleared (already an M0 entry criterion). Additional permission-dependent steps are flagged inline as **[PERM: …]**: computer-use grants for visual QA (AntiChat, Finder), `sudo` for `powermetrics` (AT-NFR-B1), `purge` (AT-NFR-U1) and `fs_usage` (AT-090), and macOS Screen Recording for `tools/visual/capture.sh rec`. If one is refused: write the exact command and error into `docs/research/QUESTIONS.md`, continue with tasks that don't need it, then ask.
2. **AT runner.** Every AT command is executed as `tools/at/run.sh <AT-ID> -- <command>` (created in M1.T02). It tees stdout/stderr to `build/at/<AT-ID>/<YYYY-MM-DD>.log`, writes `build/at/<AT-ID>/result.json` (`{"id","date","commit","cmd","exit","pass"}`) and exits with the command's status. "Pass" below always also means "artefact committed" (PRD §1.4 rule 1). For brevity the blocks list only the inner command.
3. **Test commands.**
   - Unit (SwiftPM): `make test-unit FILTER=<TestSuite>` → `swift test --parallel --filter <TestSuite>` over the root package (environment §8).
   - Integration (stub): `make test-integration-stub FILTER=<TestSuite>[/<method>]` (XPC helper + tiny models + ScriptedEngine; Xcode target `AntiChatIntegrationTests` in `App/IntegrationTests/`, created in M1.T02).
   - Integration (real): `make test-integration-real TIER=min|T0|T1|T3|evil-T1 FILTER=<TestSuite>[/<method>]`.
   - UI: `xcodebuild test -workspace AntiChat.xcworkspace -scheme AntiChat-UITests -destination 'platform=macOS,arch=arm64' -only-testing:AntiChatUITests/<Class>[/<method>]` (scheme created in M1.T02; launch arguments per test-strategy §4.2).
   - Perf: `make perf METRIC=<NFR id without prefix> TIER=<T0..T4|na> [RUNS=20]` → merges into `build/perf/report.json` (schema in M1.T26).
4. **Models.** Until M2's signed catalog, models come from `catalog/dev.yaml` (created in M1.T02; compiled to `catalog/dev-catalog.json`) via `make models-dev TIER=min|T0|T1|T3|evil-T1` (environment §6 tags; in M1 the fetch runs through M0's `tools/dev/hf-fetch.py`, anonymous, pinned, gated repos refused; `antichat-cli` replaces it in M2). 4. **Synchronous fallback:** if a send would exceed 85% and no summary covers it, compact synchronously before the request (status line `status.thinking`); this is the case counted by the 5% bound. The notice appears in the thread when the summary is first used (R-009 AC2).
5. `OversizeGuard`: a single user prompt whose token estimate > model context − reserved output → rejected before inference with `ctx.tooLarge` (suggest attaching as a file); the text stays in the composer.
6. Truncated-summary guard (Osaurus) → summary failure keeps the original messages and retries next idle.

#### Known failure modes & fallback
- Computer-use grant refused **[PERM]** → record in QUESTIONS, run XCUITest screenshot capture (`-only-testing:AntiChatUITests/VisualCaptureTests` saves the same states) so scorers still get images; motion/H1/H2 recordings then need Screen Recording permission or stay open (exit blocked until run).
- Scorer disagreement persists after the third scorer → median rule (rubric §4), no re-scoring by the builder.
- ★ screen < 4.5 → fix and re-score (up to 3 fix attempts per PRD §1.4 rule 2, then major amendment).

#### Rollback
Runbooks and scripts are additive; revert the commit to remove them. A failed exit leaves the milestone `in progress` (README) — nothing to undo in the app.
