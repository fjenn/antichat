## Signing modes used throughout this file
One variable, `SIGNING_MODE`, selects the identity (ci-release §3, §4). Until Q-003 is answered, **every artefact is `adhoc` or `dev` and labelled `UNNOTARIZED`**; notarization, stapling, production keys and production deploys happen only in M10.T10.

| Mode | Identity | Timestamp | Hardened runtime | Notarize/staple | DMG name | Feed | Who can open it |
|---|---|---|---|---|---|---|---|
| `adhoc` | `-` | `--timestamp=none` | yes | skipped | `AntiChat-<ver>-UNNOTARIZED.dmg` | `appcast-dev.xml` only | this Mac; other Macs after Privacy & Security → "Open Anyway" |
| `dev` (default for M10 RCs) | `Apple Development: <name> (<TEAMID>)` (exists today, Q-003); `lib/identity.sh` reads it with `security find-identity -v -p codesigning \| grep -m1 "Apple Development"` (falls back to `adhoc` with a warning if absent) | `--timestamp=none` | yes | skipped | `AntiChat-<ver>-UNNOTARIZED.dmg` | `appcast-dev.xml` only | as adhoc; TCC grants survive rebuilds (stable designated requirement) |
| `devid` | `Developer ID Application: <name> (<TEAMID>)` | `--timestamp` | yes | **yes** | `AntiChat-<ver>.dmg` | `appcast.xml` (stable/beta) | any Mac, standard first-open dialog only |

**Library validation note (applies to `adhoc` only):** a hardened-runtime app with library validation refuses ad-hoc-signed frameworks ("mapped file has no Team ID and is not a platform binary"). Therefore `adhoc` builds add `com.apple.security.cs.disable-library-validation` to the **app and helper entitlements only in `adhoc` mode** (file `tools/release/entitlements/adhoc-overrides.plist`, merged by `sign.sh`), and `dev`/`devid` never do (same Team ID everywhere). `verify-signing.sh` fails if this entitlement appears in a `dev` or `devid` build. Prefer `dev` for every RC handed to anyone.

## Hosting and accounts before the human steps (PRD §9)
No public GitHub repo, `gh` auth or Vercel login is assumed during the build (PRD §9 "Public repo…"; M7 "Vercel account access"). Every dev-form check therefore has a **local form**, used whenever `gh auth status` or `vercel whoami` fails:
- **Local host:** `tools/release/feed-server.py --root build/serve --bind 0.0.0.0 --port 8765 --log build/serve/requests.log` serves `site/dist/` plus `build/release/*.dmg`, `appcast-dev.xml` and `catalog/v2/`; the Tart VM reaches the host at its NAT gateway (`tart ip` side: `192.168.64.1`, confirm with `route -n get default` inside the VM). `DEV_BASE_URL` (default `http://192.168.64.1:8765`) is passed to `make site` and `appcast.sh` so the dev download button and dev appcast enclosures point there.
- **Vercel preview** (when `vercel whoami` succeeds): same files via `make site-deploy-preview`; Deployment Protection (Vercel Authentication) must be off for `antichat-site` previews or Sparkle/VM fetches get 401 (`vercel project` settings; record the change).
- **GitHub:** `release.yml` is linted (`actionlint`, pinned in `tools/toolchain.lock`) and executed locally through `tools/release/release.sh` (the same steps); the GitHub run, `gh release`, `gh secret` and GitHub-hosted DMG URLs are `pending (public repo, PRD §9)`.
