## Conventions used by every task in this file

- **Precondition Q-007 (permission):** every task except reading/writing docs needs building and running code in `~/AntiChat` (`make build`, `swift test`, `xcodebuild test`, launching the app). If the sandbox, the auto-mode classifier or macOS refuses, write the exact command and error into `docs/research/QUESTIONS.md` under Q-007, continue with any task that does not need it, then ask (PRD §1.5.1).
- **Other permission-dependent steps** are flagged inline with **[perm: …]**: TCC grants to the test runner (Accessibility, Screen Recording, Notifications), `tccutil reset`, an admin password (`sfltool`, `sysadminctl`), Tart VM creation, and the computer-use `request_access` grant for AntiChat, Finder, TextEdit and System Settings.
- **Handling every [perm] step (no guessing, no waiting):** (1) at the start of M8, check each grant once — `tools/ci/tcc-preflight.sh` (new, 10 lines): `AXIsProcessTrusted` for the terminal/xcodebuild runner via `osascript -e 'tell application "System Events" to get UI elements enabled'`, and for the dev build via its DEBUG `-PrintPermissionStatus YES` hook (prints accessibility/inputMonitoring/screenCapture/notifications/location as JSON) — and write the result to `build/at/M8-perm-preflight.json`. (2) The dev build used for every TCC-dependent test is signed with `SIGNING_MODE=dev` if an Apple Development identity exists in the keychain (`security find-identity -v -p codesigning | grep "Apple Development"`), else ad-hoc; with ad-hoc signing a grant is lost on every rebuild (cdhash changes), so TCC-dependent tests run on **one** build per session, built before the grants are checked. (3) Missing grant → run every part of the AT that does not need it (DEBUG hooks, spies, unit tests), mark only the TCC-dependent sub-steps `not run: perm <service>` in the AT log, record the exact service and command in `QUESTIONS.md` under Q-007, continue, and ask once at the milestone exit (PRD §1.5.1). An AT with a `not run: perm` sub-step is **not passed**; the M8 exit lists it as open (same rule as AT-226). Never tick a system dialog by guessing; never loosen a check to avoid a grant.
- **Commands** come from environment §8 (Makefile from M1): `make test-unit FILTER=<TestClass>` (= `swift test --parallel --filter`), `make test-integration-stub FILTER=…`, `make test-integration-real TIER=… FILTER=…`, `make perf METRIC=<id> TIER=<cap>`, `make test-ui-smoke`, `make test-offline STEP=<step>` (M2 wiring), `make test-install` (built in M8.T11), `make test-visual SCRIPTS="vq-## …"` (space-separated, as M1/M3/M7). UI tests: `xcodebuild test -workspace AntiChat.xcworkspace -scheme AntiChat-UITests -destination 'platform=macOS,arch=arm64' -only-testing:AntiChatUITests/<Class>/<method> -resultBundlePath build/at/<AT-ID>/<date>.xcresult`. Launch args from test-strategy §4.2 (`-UseScriptedEngine`, `-ANTICHAT_DEV_CONTAINER`, `-OfflineOnly YES`, `-FakeHardware`, `-FixedClock`).
- **Artefacts:** every AT writes `build/at/<AT-ID>/<yyyy-mm-dd>.log` (stdout + the pass/fail line `AT <id> PASS|FAIL <metric>=<value>`) and, where named, a JSON result. Perf numbers go to `build/perf/report.json` under the key `NFR-<id>`. Visual QA goes to `build/visual/<version>/<script>/`.
- **Visual capture helper:** `tools/visual/cap.sh <script> <checkpoint>` writes `build/visual/$VER/<script>/<checkpoint>.png` of AntiChat's front window. If it does not exist yet, create it (5 lines): read `{x, y, w, h}` with `osascript -e 'tell application "System Events" to tell process "AntiChat" to get {position, size} of front window'`, then `screencapture -x -o -R"$x,$y,$w,$h" "$out"`. The QA agent views the same state with the computer-use `screenshot` tool and scores it on [`parity-rubric.md`](../research/10-architecture/design-system/parity-rubric.md) §1 (L, V, C, S, K, A) against the screen's bar in §3. Keys marked **(new)** below do not exist yet: add them to `copy-deck.md` §-section named in the task with exactly the given English string, then regenerate `Localizable.xcstrings` (`python3 -I tools/ci/copy-sync.py --emit`). #### Steps
0. Fixtures for the schema shipped so far: for every identifier in the current migrator (in order) run `make-db-fixture.py --upto <id>` → `fixtures/chats/db/v<N>.sqlite`; write `migrations.lock`; generate both `future-v999` variants.
1. In `MigrationRunner.run(path:)` (runs **before** the writable `DatabasePool` is created, because creating it can write `-wal`/`-shm`):
   1. If `antichat.sqlite` does not exist (first launch), skip to 1.2 (no backup for an empty DB). Else open `DatabaseQueue(path:, configuration: readonly)` (`Configuration.readonly = true`) and evaluate `let superseded = try queue.read { try migrator.hasBeenSuperseded($0) }`. If true: keep only that read-only connection, do not migrate, publish `AppLaunchState.newerData`, and the app shows `NewerDataWindow` (blocking, no sidebar) with `storage.newerVersion` + button **[Update AntiChat]** (calls `UpdaterService.checkForUpdates()` if present, else opens the URL in `Config/Endpoints.plist` key `DownloadURL` (new key; dev value = the Vercel preview site `/download`, M2.T03 `site-dev` pattern)). Nothing is written (no backup, no WAL checkpoint, no `network_activity` row).
   2. Else close the read-only queue, open the normal `DatabasePool`, and `let pending = try pool.read { try !migrator.hasCompletedMigrations($0) }`. If pending: `BackupService.preMigration(pool:)` → `try pool.backup(to: DatabaseQueue(path: "<AppSupport>/AntiChat/Backups/pre-v<targetN>-<yyyyMMdd-HHmmss>.sqlite"))`, then `fsync` the file (`FileHandle.synchronize()`), then verify by opening it and running `PRAGMA integrity_check` == `ok`.
   3. `try migrator.migrate(pool)`. On any throw: close the pool, move the live DB aside to `Backups/failed-<ts>.sqlite`, copy the pre-migration backup back to `antichat.sqlite` (delete stale `-wal`/`-shm` first), re-open **without** migrating (read-only), and publish `AppLaunchState.migrationFailed(error)` → `MigrationFailedWindow` with `storage.migrationFailed` and actions **[Restore backup]** (opens `RestoreBackupSheet`) · **[Report a problem]** (M8.T09 form with the error code prefilled).
2. Daily rolling backup: `BackupService.scheduleDaily()` runs when the app has been idle ≥ 60 s (no turn streaming, no import) and the newest `Backups/daily-*.sqlite` is older than 24 h; writes `Backups/daily-<yyyyMMdd>.sqlite` via `backup(to:)`, keeps the newest **7** `daily-*` files and the newest **3** `pre-v*` files, deletes older ones. Runs at `.utility` priority. Never runs for the incognito in-memory DB.
3. Restore UI: Settings → Privacy & Data → row **Restore from backup** (`set.privacy.restore` (new): "Restore from backup") opens `RestoreBackupSheet`: list of backups (date, kind Daily/Before update, size, chat count read via a read-only `DatabaseQueue`), button **[Restore]** → confirm (`backup.restore.confirm` (new): "Replace your current chats with the backup from {date}? Your current data is saved as a backup first.") → take a `pre-restore-<ts>.sqlite` backup of the current DB, swap files with the pool closed, relaunch the app (`NSApp.relaunch` helper: spawn `open -n <bundle>` then terminate).
4. Signposts: `migration` interval (category `store`) around step 1.3; `sidebarFirstPaint` must come after `migration` end (used by AT-219 in M10).
5. Log lines (category `store`): versions from/to, backup path, duration; never content.
6. Change the `storage.newerVersion` string in copy-deck §8 to R-301 AC3 verbatim: "This data was made by a newer AntiChat. Please update." (button stays "Update AntiChat"; AC strings are verbatim, minor amendment). Add copy keys (copy-deck §8/§9): `set.privacy.restore`, `backup.restore.confirm`, `backup.kind.daily` ("Daily"), `backup.kind.preUpdate` ("Before update"), `backup.restore.cta` ("Restore").

#### Definition of done
- `fixtures/chats/db/v<head>.sqlite` and `migrations.lock` committed; every later M8 task's migration adds its row to both.

#### Known failure modes & fallback
- `backup(to:)` slow on a multi-GB DB (imports) → launch exceeds NFR-U1 → show the S-04-style "Updating your chats…" progress window during migration only (migrations are rare); minor.
- Disk full during backup → do **not** migrate; show `download.diskFull`-style sheet with `storage.backupNoSpace` (new: "AntiChat needs {gb} GB free to update your chats safely.") and [Open Storage]; minor.
- `hasBeenSuperseded` false positive after a dev branch registered then dropped a migration → only in DEBUG (`eraseDatabaseOnSchemaChange`); release builds never drop identifiers (lock test (d)).

#### Rollback
Revert the `M8.T01` commits. No schema change is made by this task itself. If a user DB was restored by mistake, the `pre-restore-<ts>.sqlite` file is the recovery copy.

#### Steps

2. `MemoryTool` definition (registered in the tool registry as `memory`, load-when-needed group "Memory", shown on the Tools page; disabled when Settings → Personalization → Memory is Off or Paused, when `chat.memory_enabled == false`, in incognito, and in Evil chats unless `Defaults[.useMemoryInEvil]`):
   ```json
   {"name":"memory","description":"Save, update, delete or view facts about the user. Save only when the user asks you to remember something, or when you propose it and the user agrees.",
    "parameters":{"type":"object","required":["action"],"properties":{
      "action":{"enum":["view","save","delete"]},
      "topic":{"type":"string","maxLength":40,"description":"Short topic, e.g. Food, Work, Family"},
      "scope":{"enum":["global","project"],"default":"global"},
      "key":{"type":"string","maxLength":64},
      "value":{"type":"string","maxLength":500},
      "sensitive_category":{"enum":["none","health","sexuality","religion","politics","finances"],"default":"none"}}}}
   ```
   - `view` returns the topic list with item keys (≤ 2,000 chars, LibreChat token cap analogue).
   - `save` → `MemoryUpdateDecider.decide(new:, scope:, topic:)`: nearest k = 5 active items in the same scope (any topic) by cosine on `chunk_vec`; if the top cosine ≥ 0.92 → UPDATE that item without an LLM call; else, if any neighbour ≥ 0.60, run the ported mem0 prompt on the chat model with a JSON grammar `{"event":"ADD|UPDATE|DELETE|NONE","id":"<item id or null>","text":"<merged text>"}` at temperature 0; else ADD. Thresholds live in `MemoryConfig` (tuned once on `paraphrase-100` and recorded in the task commit).
   - **Sensitive topics (R-060 AC3; a privacy choice, not a content filter, VISION §2.4):** if `sensitive_category != none` and `Defaults[.memoryIncludeSensitive] == false`, the executor does not store the item and returns `{"stored":false,"reason":"sensitive_topics_off"}` to the model; nothing in the chat is blocked or rewritten. The topic `sensitive_category` is set from the tool argument; the tool description tells the model to tag those five categories. The R-241 audit pattern list (test-strategy §9.3) must not match this code (identifiers use `sensitive`, not `unsafe/harmful/policy`); if it matches, add an allow-list entry with the justification "R-060 AC3 privacy setting" (lead sign-off).
   - Every write appends a `memory_event` and emits `ToolResult` part metadata `{memoryEventIDs:[…]}` so the UI (M8.T03) renders `act.memory` "Memory updated ▸" with [Undo].
