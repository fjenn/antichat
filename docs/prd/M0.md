## Conventions for every M0 task

### C1. Permission preconditions (Q-007 type, PRD §1.5 case 1)
Each task lists the permission IDs it needs. If the sandbox, an auto-mode classifier or macOS refuses one, write the exact command and error into `docs/research/QUESTIONS.md` (new `Q-###`, linked from the task), continue with tasks that do not need it, then ask.

| ID | Permission | Typical command that must be allowed |
|---|---|---|
| **P-CLONE** | clone public repos into `~/AntiChat` and `/tmp` | `git clone https://github.com/osaurus-ai/osaurus /tmp/osaurus` |
| **P-BUILD** | build and run code in `~/AntiChat` (Xcode, SwiftPM, CMake, Python `-I`) | `xcodebuild …`, `swift build`, `cmake --build …` |
| **P-NET** | outbound HTTPS to github.com (incl. release assets), huggingface.co (anonymous, D-007), pypi/files.pythonhosted.org, registry.npmjs.org, mise/uv release hosts, openslr.org (LibriSpeech, T05), commons.wikimedia.org + upload.wikimedia.org (CC0 photos, T01), api.github.com (licence API, T12) | `curl -fsSL https://huggingface.co/api/models/<repo>/revision/<sha>` |
| **P-DL** | model weight downloads inside the 400 GB budget, no per-batch confirmation (D-003, D-007) | `python3 -I tools/dev/hf-fetch.py …` |
| **P-CU** | computer-use grants for AntiChat, System Settings, Finder (visual QA, TCC prompt screenshots) | `request_access(["AntiChat","System Settings","Finder"])` |
| **P-ADMIN** | admin/sudo steps (driver or pref-pane install, `purge`, `dnctl`/`pfctl`) | `sudo purge`; installing BlackHole 2ch; Network Link Conditioner |
| **P-PRIV** | the private ChildSafetyCheck calibration fixtures exist at `~/AntiChatPrivateFixtures` on the runner (never in git, environment §4) | `test -d ~/AntiChatPrivateFixtures/csc` |

P-ADMIN and P-PRIV have documented no-admin / no-fixture fallbacks in the tasks that use them, so they never block the milestone; they only change the evidence label (`[EMULATED]`, `[PENDING-PRIVATE]`).

### C2. Branches, commits and promotion
- Spike work happens on `spike/s-<n>-<slug>` (e.g. `spike/s-3-xpc-engine`). Evidence-only code stays there; the branch is pushed/kept, never deleted, and its last commit SHA is cited in the report.
- **Promoted to `main` (via independent `/code-review` at high effort, PRD §1.4 rule 5)** only: the scaffold, pins and bootstrap (T01), the vendored closure and `tools/vendor-sync` (T02/T14/T03), `tools/dev/hf-fetch.py` and `tools/perf/*` (T04), `tools/release/sign.sh` + `verify-signing.sh` (T12), `tools/d012/switch.py` (T13). Everything else is re-implemented or promoted by review inside the milestone that owns its gap (M1 G-009/G-010, M2 G-011/G-051, M3 G-036…G-039, M4 G-041/G-048, M5 G-045, M8 G-058).
- Closing commit per task: `M0.T##: <title>` listing the ATs run and the result (PRD §1.4 rule 3), ending with the session's attribution line.

### C3. Spike report and registry row
Every spike writes `docs/research/07-spikes/S-<n>-<slug>.md` with exactly these sections: **Question** (from `selection.md` §9 or the PRD row) · **Method** (commands, models with `repo@commit`, tier cap, run count) · **Result** (table: metric, p50, p95, n, target NFR-ID, pass/fail, scaled?) · **Evidence** (artefact paths under `build/at/AT-M0-##/`, `build/perf/report.json` keys, branch@sha) · **PRD impact** (fallback adopted? amendment ID? K-IDs closed or carried). Tag every unsourced statement `[INFERENCE]` or `[ASSUMPTION]` (PRD §1.4 rule 1).

### C4. Gate scripts and artefacts
- Each gate has one script `tools/m0/at-m0-NN.sh` (bash, `set -euo pipefail`), run as `make m0-gate AT=AT-M0-NN`. The Makefile target is: `m0-gate: ; tools/m0/$(shell echo $(AT) | tr A-Z a-z).sh`.
- Each script writes `build/at/AT-M0-NN/<YYYY-MM-DD>.log` (full stdout/stderr) and `build/at/AT-M0-NN/result.json` = `{"at":"AT-M0-NN","pass":true|false,"checks":[{"name":…,"value":…,"bar":…,"pass":…}],"commit":"<sha>","host":{…}}`, and exits 0 only if `pass` is true. Committed: `result.json` and the log (logs > 5 MB are gzip'd). PRD §1.4 rule 1: a gate "passes" only with these artefacts committed.
- Performance numbers go to `build/perf/report.json` under `m0.<metric>.<tier>.<model>` = `{"p50":…,"p95":…,"n":…,"unit":"s|tok/s|GB","nfr":"NFR-C1","target":…,"scaled_from":"M5 Max S4"|null,"label":"measured|[EMULATED]|[SCALED]"}`. `tools/perf/report.py merge` appends without overwriting earlier keys.

### C5. Tier-cap emulation and scaling (test-strategy §6, hardware-tiers §7, model-matrix §6.2)
- Dev Mac: M5 Max 128 GB (S4, T4). Tier caps are emulated by the budget **B** from `hardware-tiers.md` §2.2: `T0=4.0`, `T1=9.5`, `T2-24=16`, `T2-32=21`, `T2-36=24`, `T3-48=36`, `T3-64=48` GB.
- MLX in the helper: `--tier-cap <T>` sets mlx-swift's GPU memory limit and wired limit to B (`MLX.GPU.set(memoryLimit:)` and the wired-limit API at `f5b0677`; record the exact API names used in the S-3 report). llama-server and sd-server: B is enforced by the prototype scheduler (refuse a load whose catalog footprint + current resident > B) and checked after the fact by sampling `phys_footprint` of every AntiChat process + `MTLDevice.currentAllocatedSize` every 100 ms (`tools/perf/footprint.py --pids …`).
- Speeds are scaled to other chips with `tools/perf/scale.py` (decode × bandwidth ratio; prefill and diffusion × pp512 ratio; chip table from `hardware-tiers.md` §1.1 and §2.3). Scaled values are labelled `[SCALED]`; they are hypotheses for hardware we do not have (D-003, Q-004).
- Every measurement: AC power, `pmset -g therm` normal, no other GPU job, ≥ 20 runs unless the task states otherwise, p50/p95 (nfr.md "Statistics").
